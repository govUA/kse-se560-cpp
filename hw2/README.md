## 1. Program Organisation

The original single-file program has been decoupled into three separate files:

- `fibonacci.hpp`: Function declarations with `#pragma once` header guard.
- `fibonacci.cpp`: Definitions of recursive and iterative Fibonacci algorithms.
- `main.cpp`: Program entry point calling the functions and printing results via `std::print`.

### Build & Link

```bash
# 1. Compile translation units to object files
clang++ -std=c++23 -c main.cpp -o main.o
clang++ -std=c++23 -c fibonacci.cpp -o fibonacci.o

# 2. Link object files into executable binary
clang++ main.o fibonacci.o -o fibonacci_app

# 3. Execute
./fibonacci_app
```

```text
 1 
 55 
 1 
 55 
```

## 2. Stages Exploration

```bash
# Step 1: Preprocess to pure expanded C++ source
clang++ -std=c++23 -E fibonacci.cpp -o fibonacci.ii

# Step 2: Compile preprocessed source into assembly code
clang++ -std=c++23 -S fibonacci.ii -o fibonacci.s

# Step 3: Assemble into an object file
clang++ -c fibonacci.s -o fibonacci_from_asm.o

# Step 4: Link assembly-derived object file with existing main.o
clang++ main.o fibonacci_from_asm.o -o fibonacci_from_asm_app

# Step 5: Run to verify identical behavior
./fibonacci_from_asm_app
```

### Verify Output


## 3. Explanation

### File Contents, Formats, and Stages

- **`.ii` (Preprocessed Source):** A text file generated by the preprocessor (`-E`). It contains full C++ code with
  expanded header files, stripped comments, and processed preprocessor directives.
- **`.s` (Assembly File):** A text file produced by the compiler (`-S`). It contains human-readable assembly
  instructions targetted to the host processor architecture (x86_64).
- **`.o` (Object File):** A binary file (ELF on Linux) generated by the assembler (`-c`). It contains compiled machine
  code instructions and an exported/imported symbol table with unresolved memory offsets.
- **Executable Binary:** A binary file produced by the linker (`ld`). It bundles code sections, resolves symbol
  cross-references, and binds program entry points into a runnable format.

### Declarations vs Definitions

During compilation of `main.cpp`, the compiler only needs the function declaration (signature) to verify argument types,
return types, and generate the correct calling convention conventions, leaving unresolved placeholder relocations.
Linking requires the function definition (actual machine instructions) to resolve those relocations into valid
addresses.

### Include Guards

An include guard (`#pragma once` or `#ifndef` macro) ensures a header file is parsed only once per **translation unit
** (a single `.cpp` file compilation). It does **not** stop a second `.cpp` file from reading the header, because each
source file is parsed in an independent compiler invocation.

### Rebuilding Artifacts

- Modifying only a function body in `fibonacci.cpp` requires recompiling only `fibonacci.o`. `main.o` remains completely
  valid because the interface did not change.
- Modifying a declaration in `fibonacci.hpp` requires rebuilding both `main.o` and `fibonacci.o`, as the calling
  contract and signatures changed for both the caller and the implementer.

## 4. Errors Exploration

### 4.1. Missing Header in `main.cpp`

Temporarily removed `#include "fibonacci.hpp"` from `main.cpp`.

**Command:**

```bash
clang++ -std=c++23 -c main.cpp -o main_broken.o
```

**Compiler Error Output:**

```text
main.cpp:5:26: error: use of undeclared identifier 'fibonacci_recursive'
    5 |      std::print(" {} \n", fibonacci_recursive(2));
      |                           ^
main.cpp:6:26: error: use of undeclared identifier 'fibonacci_recursive'
    6 |      std::print(" {} \n", fibonacci_recursive(10));
      |                           ^
main.cpp:8:26: error: use of undeclared identifier 'fibonacci_iterative'
    8 |      std::print(" {} \n", fibonacci_iterative(2));
      |                           ^
main.cpp:9:26: error: use of undeclared identifier 'fibonacci_iterative'
    9 |      std::print(" {} \n", fibonacci_iterative(10));
      |                           ^
4 errors generated.
```

**Explanation:**
The compiler processes each translation unit independently. Without header declarations, it has no knowledge of
identifiers `fibonacci_recursive` and `fibonacci_iterative`, their parameter types, or return types, making type
checking and call instruction generation impossible.

### 4.2. Missing Object File at Link Time

Attempted to link without `fibonacci.o`.

**Command:**

```bash
clang++ main.o -o broken_app
```

**Linker Error Output:**

```text
/usr/bin/ld: main.o: in function `main':
main.cpp:(.text+0x39): undefined reference to `fibonacci_recursive(int)'
main.cpp:(.text+0x67): undefined reference to `fibonacci_recursive(int)'
main.cpp:(.text+0x93): undefined reference to `fibonacci_iterative(int)'
main.cpp:(.text+0xc1): undefined reference to `fibonacci_iterative(int)'
clang++: error: linker command failed with exit code 1 (use -v to see invocation)
```

**Explanation:**
The compilation phase succeeded because declarations were present. However, the linker `/usr/bin/ld` could not find
definitions for the referenced symbols in any of the supplied object files, resulting in unresolved symbols and linking
failure.
